# Android: устанавливаемая оболочка сайта

Приложение `ru.zovoceana.app` открывает **https://zovoceana.ru/** в Android WebView.
Каталог, оформление заказов и остальные страницы загружаются с сервера: обновление
сайта видно в приложении без пересборки APK. Без интернета интерфейс магазина
недоступен; приложение показывает ошибку с кнопкой повторной загрузки.

Для iPhone сохраняется установка сайта через Safari: «Поделиться» → «На экран
Домой». iOS-проект и публикация в App Store не нужны.

## Сборка

Нужны JDK 17, Android SDK (platform 35, build-tools 35.0.0) и принятые лицензии SDK.
Можно установить их через Android Studio. Gradle Wrapper включён в проект.
Указать `ANDROID_HOME` или `sdk.dir` в локальном `local.properties`.
На этой машине инструменты также могут находиться в игнорируемой `.android-tools/`.

Из корня репозитория в PowerShell 7:

```powershell
# Тестовая сборка, автоматически подписанная стандартным debug-ключом.
./android-app/scripts/build.ps1 -Variant Debug

# Один раз создать собственный ключ для распространяемой версии.
./android-app/scripts/new-signing-key.ps1
./android-app/scripts/build.ps1 -Variant Release
```

Результат: `app/build/outputs/apk/release/app-release.apk` внутри `android-app`.
Скрипт release-сборки также автоматически копирует APK в
`public/downloads/zov-oceana.apk` — это файл для кнопки скачивания на сайте.
На Linux/macOS можно использовать `./gradlew :app:assembleRelease :app:lintRelease`
из `android-app`, предварительно настроив JDK/SDK и файл подписи.

**Сохранить `zovoceana-release.jks` и `signing.properties` в защищённой резервной
копии.** Они исключены из Git. Следующие версии APK должны иметь тот же ключ и
applicationId, больший `versionCode`. Потеря ключа не позволит установить обновление
поверх выпущенного приложения. Debug APK не предназначен для распространения.

APK можно передавать файлом или размещать на своём HTTPS-сайте. При установке
пользователь разрешает установку из выбранного браузера/мессенджера; Android и
Play Protect могут показывать системные проверки. Автоматических обновлений
оболочки нет: новый APK устанавливается вручную. Не публикуйте файлы подписи.

## Поведение и ограничения

- Основной адрес задаётся в `app/src/main/res/values/strings.xml`; при смене домена
  нужно также обновить AndroidManifest и пересобрать APK.
- Внутри остаются только HTTPS-страницы основного домена. Внешние ссылки открываются
  соответствующим приложением или браузером. Поддержаны `tel`, `mailto`, `tg`,
  банковские `bank…`, `sbp`, `sberpay`, `tinkoffbank` и безопасная обработка `intent:`.
- Cookies/localStorage сохраняются. Для Telegram предусмотрено отдельное WebView-окно,
  сохраняющее связь с исходной страницей. Нужна проверка реального Telegram-входа
  на устройстве: поведение провайдера авторизации может зависеть от WebView.
- Внешние платёжные ссылки открываются снаружи; встроенный виджет сайта остаётся
  в WebView и требует проверки на устройстве, включая доверие к CA банка.
  Возврат в приложение по HTTPS-ссылке требует
  настройки Android App Links. Файл `static/.well-known/assetlinks.json` уже содержит
  отпечаток созданного release-ключа и копируется сборкой в `/.well-known/assetlinks.json`.
  Его нужно выложить вместе с сайтом по HTTPS без авторизации и перенаправлений.
  При смене ключа обязательно заменить отпечаток. До выкладки и проверки домена
  Android возвратная ссылка может открыться в браузере; приложение можно
  открыть вручную и проверить статус заказа. Разрешение по домену уже есть в manifest.
- Отпечаток ключа: `keytool -list -v -keystore zovoceana-release.jks -alias zovoceana`.
  Публикуется только отпечаток сертификата, никогда ключ или пароли.
- SSL-ошибки не игнорируются; HTTP и mixed content заблокированы внутри WebView.
  Дополнительные CA не устанавливаются на телефон. Доверие к сертификатам банка
  во внешнем браузере/приложении определяется этим браузером/приложением.
- Доступа JavaScript к Android API через мост нет. Выбор фото использует системный
  диалог без разрешения на доступ ко всем файлам. Push-уведомлений в оболочке нет.
- Текущая серверная привязка сессии к IP остаётся: при смене Wi-Fi/мобильной сети
  сайт может попросить войти заново, как и в обычном браузере.

Перед распространением проверить на физическом Android: первый запуск, вход по
паролю и Telegram, перезапуск с сохранённой сессией, корзину, оплату картой/СБП,
возврат после оплаты, кнопку «назад», выбор фото, поворот экрана, клавиатуру и
восстановление после отключения сети. Сборка и lint не заменяют эти проверки.
